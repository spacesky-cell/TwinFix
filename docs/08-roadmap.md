# 08 路线图

TwinFix 当前版本为 **v0.1.0-alpha**。核心闭环、40 例基准测试套件与 CI 已可复现；以下方向按优先级排序。

## 近期

- **合并队列（merge queue）接入**：缩小“验证后到合并前”的竞态窗口，支持 GitHub 与 GitLab。
- **真实项目适配指南**：补充 `project.config.commands` 的示例，覆盖 Maven 多模块、Gradle、monorepo 等常见布局。
- **评测门禁进入 CI**：在具备模型配额的环境中运行 fast suite，并作为 PR 合并条件。
- **生产化部署指南**：反向代理、鉴权、TLS、外部 PostgreSQL / Redis / RabbitMQ 与资源规划。

## 中期

- **更多语言 Profile**：按统一接口扩展（例如 Ruby、PHP、Rust）。
- **更强的代码智能**：跨文件类型推断、调用图可视化、变更影响分析。
- **修复策略**：多方案生成与对比、补丁最小化、回滚预案。
- **可观测性**：更丰富的指标、告警与运行报表。

## 长期

- 与更多代码托管与 CI 平台集成。
- 面向团队的多租户、配额与审计能力。
- 在真实生产仓库中的规模化验证。

## 已知限制

- 默认配置面向本地单机演示：关闭鉴权、端口绑定 `127.0.0.1`；对外部署前必须按 [`SECURITY.md`](../SECURITY.md) 配置。
- 孪生环境需要可用的 Docker Compose 或 Kubernetes 集群；真实项目需提供可构建的镜像与依赖。
- 单次事故的成本与耗时取决于模型、仓库规模与测试套件。
- GitLab 与 Kubernetes 适配器需要在目标环境中按文档完成联调。
